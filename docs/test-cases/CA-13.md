# Test cases - CA-13: Editarea unui document

User Story: Ca utilizator, vreau să corectez un document salvat, ca cifrele să fie corecte.

Abordare de dezvoltare: tradițională (implementare, apoi teste).

## Cum funcționează

- Pe ecranul unui document (Acasă → document) apare „Editează documentul”, deasupra lui „Șterge documentul”. Se poate edita orice document: cheltuială manuală, bon scanat sau factură scanată.
- Formularul are aceleași câmpuri și aceleași verificări ca „Adaugă o cheltuială” (US-03), preluate din aceeași componentă: magazin (sau „Pentru ce ai plătit?” la o cheltuială manuală), sumă, data (calendar, fără date din viitor), categorie, plată și notă.
- „Salvează modificările” trimite `PATCH /api/documents/{id}` cu toate câmpurile. Profilul documentului (Personal / Firmă) și ora nu se schimbă.
- La o cheltuială manuală, singurul ei produs urmează modificarea (nume, sumă, categorie). La un bon sau o factură scanată se schimbă doar valorile documentului; produsele rămân așa cum au fost citite și verificate, deci suma documentului poate ajunge diferită de suma produselor.
- La revenirea pe ecranul documentului și pe Acasă, datele se reîncarcă: lista și totalul zilei arată valorile corectate.

## Pregătire pentru verificarea manuală

1. Serverul pornit: `cd server` și `npm run dev`.
2. Aplicația pornită: `cd mobile` și `npx expo start`, deschisă pe un telefon în Expo Go, cu un cont confirmat. La prima pornire după această versiune, `expo start` regenerează tipurile rutelor (ruta nouă `edit-document/[id]`).
3. Pe Acasă există o cheltuială manuală și, dacă se poate, un bon scanat, în luna curentă.

## Rularea testelor automate

Din rădăcina repository-ului:

```bash
npm test
npm run test:coverage
```
